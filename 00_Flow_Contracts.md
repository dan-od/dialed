## 01 → 02 (C-0102)
- Trigger: successful verify (email) or Apple sign-in with `is_new = true` or user with zero routine blocks in any term.
- Data: session; profile (name, time zone set from device on first call).
- Preconditions: on account creation the server creates the default categories only — School: Class (`protected`), Study; Life: Gym, Personal, Meal (`quiet`), Break (`quiet`); Projects: none (ASSUMED; the owner's project categories come from the seed, not defaults). No term exists until setup creates one (import review or Build it myself asks for term name + dates, prefilled from the device date). Enforced by the `POST /v1/auth/verify` and `/v1/auth/apple` handlers in one transaction.
- Success: Day renders the setup chooser (`setup` state, rendered by Flow 03's empty-Day component; options are owned and wired by Flows 02/05/06). Toast "Welcome, <first name>. Let's set up your week."
- Failure handoff: if initial sync fails → Day shows offline/stamp notice with retry; setup options needing network disabled with reason.
- Idempotency: re-entering setup is safe until a routine exists.
- Proof: e2e new account → setup visible.

## 01 → 03 (C-0103)
- Trigger: sign-in success for an account with data; app launch with valid session.
- Data: session; first sync pull (or cached SQLite).
- Success: Day for current clock. Launch splash ≤ 1.6 s, never blocks on network (renders cached data, syncs behind).
- Failure: refresh fails with `unauthorized` → `sessionEnded()`.
- Proof: cold launch offline with cache shows Day.

## 02 → 06 (C-0206)
- Trigger: Describe your week (opens Plan it with empty text), timetable import result, calendar import result.
- Data: plan id with `source` = `in_app | timetable | calendar`.
- Shared owner: Flow 06 Review screen renders all sources; timetable/calendar reviews use the "Found N classes" / "Pick calendars" pre-steps owned by Flow 02, then Approve via `POST /v1/plans/:id/approve`.
- Success: approve applies; Flow 02 shows toast "Added 6 classes to Fall term. Now tell <AI> about your projects." with Describe action.
- Failure: provider/vision errors return to Flow 02 with stamp notice and retry; text/file choice kept.
- Proof: e2e import → approve → Day shows classes.

## 02 → 05 (C-0205)
- Trigger: Build it myself. Data: the active term and its routine id; if no term exists, a small "Name your term" step (name, starts, ends; prefilled "Fall term", today → +13 weeks) creates it first. Success: routine editor for Monday, empty. Proof: e2e.

## 03 → 04 (C-0304)
- Trigger: nav + (add sheet, today, mode `day`), row tap (edit sheet for that resolved block), routine editor "Add to Mon" (mode `routine`).
- Data: `{mode, date, weekday, block?}` — block includes `routine_block_id | override_id | null`, resolved fields, `base_version`.
- Success: sheet closes, highlight + "New" chip on the row, toast with result; Undo where applicable.
- Failure: validation inline; overlap warning ("Add anyway"); version conflict toast with Reapply.
- Proof: component + e2e.

## 03 → 05 (C-0305)
Month → Routines pill; Routines back returns to Month. No data beyond navigation. Proof: navigation test.

## 03 → 06 (C-0306)
AI mark in Day header, "Describe a change to <AI>" in Routines, first-run Describe → Plan it composer (text preserved per draft in SQLite `plan_drafts`). Offline: composer opens, Send disabled with stamp notice. Proof: e2e.

## 04/05/06/09 → 08 (C-x08)
- Trigger: any local or synced change that affects today or tomorrow, or any change to lock mode / notification prefs / categories (colour, quiet).
- Data: widget snapshot v1 JSON written to App Group (Live Activity attributes are defined separately in BACKEND_SETUP §8) (`snapshot.json`): `{version:1, generated_at, time_zone, days:[resolved today, tomorrow], week:{hours_by_day, top_categories}, categories:{id:{name,color_dark,color_light,quiet}}, settings:{lock_mode, line_on, rundown_default, widget_meals}}`.
- Actions: write snapshot → `reloadAllTimelines()` → reschedule local notifications → `PUT /v1/devices/current` prefs if changed → server reschedules Live Activity jobs on revision change.
- Success: within 5 s of the change (foreground) widgets/line show new data; Live Activity jobs for affected blocks updated (ended/started) within 60 s.
- Failure: snapshot write failure logged; next foreground retries. APNs failure retried by job policy.
- Proof: device test: edit current block end time → LA end time updates; widget timeline reflects.

## 06 → 03 / 05 (C-0603)
Approve success screen "<Term> updated" with "See this week" (Week tab, root) and "Back to Routines". Data: new revision pulled before navigation (approve response includes revision; client pulls). Proof: e2e.

## 07 → 06 (C-0706)
- Trigger: `propose_changes` returns `ready` for an MCP client.
- Data: plan `{id, source:'mcp', client_name, request_text, changes, base_revision}`.
- Event: `push.chat_draft` → notification "<client> sent a plan from chat"; tap → `dialed://plan/<id>` → Review (Flow 06). Plans list shows "From <client> chat".
- Preconditions: Planner has ≥ 1 device with push; otherwise plan appears in Recent plans on next open.
- Revision: MCP client may revise with same `proposal_id` until the Planner approves/discards; after that, revision returns `plan_not_ready`/creates a new draft.
- Failure: invalid drafts never notify; errors return to the AI client.
- Proof: MCP Inspector draft → push in sandbox → review/approve on device.

## 08 → 03 / 06 (C-0803)

## 09 → 07 (C-0907)
Settings → AI assistant page: in-app provider section (Flow 06 owns), "Plan from your AI app" section (Flow 07 owns): connector URL, connect confirmation, list of connected clients from `GET /v1/connector`, disconnect.

## Idempotency, retry and concurrency summary
| Operation | Key | Retry | Concurrency |
|---|---|---|---|
| Sync push | client_mutation_id | client backoff 1–60 s | per-row version |
| Approve plan | plan id + state | safe to repeat | row lock on plan; base_revision check |
| Plan create | client `Idempotency-Key` header (uuid per Send) | client may resend | one drafting plan per user at a time (new Send cancels previous drafting) |
| Timetable upload | Idempotency-Key | resend | one import at a time per user |
| Live Activity jobs | dedupe_key `la:<device>:<block>:<date>:<start|end>` | 5 attempts | lease |
| Plan/chat pushes | dedupe_key `push:<plan>` | 5 attempts | lease |
