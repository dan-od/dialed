State coverage

  • Covered: entry, happy paths, loading, empty and first use, validation, overlap warning, permission ask, allow, deny and recovery, offline, error, retry and repeated failure, cancel, discard confirm, undo, interruption (plan finishes while you're away), out-of-date plan, success, and exits back to where you started.
  • Not applicable: roles (one person per account, and each account sees only its own data), tablet and desktop (iPhone home-screen app only for v1), login expiry and shared links (single-user home-lab server, no share links in v1), microphone permission (dictation uses the iPhone keyboard).

Accessibility

  • Keyboard: Tab moves through the phone in reading order. Esc closes the top sheet or dialog. Focus stays inside open sheets.
  • When a sheet closes, focus goes back to the button that opened it. When the screen changes, focus moves to its heading.
  • Saves, errors and plan results are announced through a live region.
  • Reduce motion swaps slides and pops for quick fades and stops the ticking colon and spinner loops.
  • Every control is a real button, input or switch with a name, 44 pt or larger.

Mocked here, proven later

  • Claude, the MCP server and every save are local fakes with fixed delays.
  • The iPhone notification prompt is a drawing. Real web push needs the app added to the Home Screen first (iOS 16.4 and later).
  • Haptics are annotations. Browser vibration is a rough stand-in and proves nothing about native feel.
  • Swipe snapping and scroll collapse use browser scrolling, not native physics.
